# Session 2 — Workshop: qualify, classify, route

No laptop needed: paper, a pen, the [handouts](handouts/).

## Exercise 1 — Role-play in pairs (35 min)

**Roles:** one **developer**, one **L1**. Swap roles after each card.

1. The trainer gives the developer a **ticket card**: the first message, plus hidden facts that only the developer knows.
2. The developer reads the first message aloud — and nothing more.
3. The L1 qualifies, using the [qualification checklist](handouts/qualification-checklist.md). The developer answers **only what is asked**, truthfully, in a developer's words (no help, no hints).
4. When the L1 thinks they have enough, they fill the [ticket template](handouts/ticket-template.md): kind, priority, identifiers, analysis, next step.
5. The developer reveals the card. Together: what was found, what was missed, which question would have found it sooner?

About 5 minutes per card. The trainer stops each round and picks one pair to share.

**Watch for:** jumping to a fix before qualifying · forgetting the identifiers · not asking "what changed?" · not asking "who else is affected?" · accepting the requested solution instead of the need.

## Exercise 2 — Fix a bad ticket (5 min, individually)

Here is a ticket as it was forwarded to L2:

> **Title:** URGENT problem
> **Description:** User says it doesn't work since the update. Please check ASAP.

List everything that is missing, then write the questions you would have asked.

## Exercise 3 — Reply and escalate (10 min, pairs)

Take one of the cards you played:

1. Write the **reply to the developer** (5 lines max): what you understood, what happens next, when they'll hear from you, what they can do meanwhile.
2. If it must go further, write the **escalation** with the [escalation template](handouts/escalation-template.md). Would the next level be able to start without asking you anything?

## Debrief questions

- Which question was the most useful today?
- On which card did you change your mind about the kind of ticket (incident / request / question)?
- Which tickets could the developer have solved alone with the right documentation? What would you add to an FAQ?
